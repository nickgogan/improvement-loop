# DD-94

> **For agents:** Every guide in `extracts/guides/` has a companion changelog file at `extracts/guides/changelog/<guide-stem>.changelog.md`. `/synthesize-guide` appends a new entry at the top of the file on every re-synthesis. Entries are terse (~10 lines), use a closed trigger-tag vocabulary, and link to the System Log entry that carries the narrative.

---

## The Constraint

**File location and naming.**

For a guide at `extracts/guides/<guide-stem>.md`, its changelog lives at `extracts/guides/changelog/<guide-stem>.changelog.md`. One-to-one mapping. The `extracts/guides/changelog/` directory already exists (created 2026-04-20 as an empty signal of intent — this DD honors that signal).

**Entry shape.** One block per re-synthesis, ~5–8 lines, hard-capped at 10:

```markdown
## 2026-04-XX — Session NN — <trigger-tag>

- Findings: <N> (+<added>, -<removed> since last synthesis)
- Added: [[finding-1]], [[finding-2]], [[finding-3]]
- Removed: [[finding-x]]   (omit line if zero)
- Structural: <1–2 lines: what changed at the guide-architectural level>
- Preserved: <`## Nick's Annotations` untouched | `<!-- PRESERVE -->` regions intact | none>
- SL: [[session-NN-<descriptor>]]
```

**Trigger-tag enum (closed vocabulary).** The header trigger-tag MUST be one of:

- `staleness-threshold` — re-synthesis triggered by accumulated source-finding count crossing the staleness threshold.
- `nick-request` — re-synthesis explicitly requested by Nick (re-framing, emphasis change, sharpened example).
- `dimension-rebalance` — re-synthesis driven by `/dimension-rebalance` reclassifying findings into or out of the guide's cluster.
- `finding-removed` — re-synthesis driven by explicit removal of one or more source findings (deduplication, deprecation, mis-classification correction).
- `structural-edit` — re-synthesis driven by a structural change to the guide template itself (e.g., a new step added, sections reordered) without a finding-set change.
- `guide-split` — split-execution entries on the source guide's final changelog and on each destination guide's first changelog (per DD-98). Source-side body line: "Split into destinations [[<destination-A-stem>]] and [[<destination-B-stem>]] per [[DD-XXX]]" where DD-XXX is the per-split DD. Destination-side body line: "Derived from source [[<source-stem>]] per [[DD-XXX]]". Amendment landed via DD-98 (Phase-3 ratification, session 74) and IB-159 (implementation, session 76).

If a re-synthesis is driven by multiple triggers, the dominant one is chosen; secondary triggers go in the Structural line. New trigger tags require a DD amendment, not ad-hoc invention.

**Append direction.** Most-recent-first. New entries are inserted at the top of the file (immediately under the file's title heading). Older entries scroll downward. This matches the SL reading convention and surfaces the latest delta without scrolling.

**Line-cap enforcement.**

- ≤10 lines (excluding header): clean.
- 11–15 lines: skill emits a warning but writes; the entry is over-budget and verbose content should be moved to SL.
- >15 lines: skill aborts the entry write and surfaces a structured report; Nick re-runs after slimming the entry.

The file itself is unbounded — entries accumulate over the guide's lifetime.

## Why

**Stability profile drives the mechanism choice.** Per spec §3.3 / §4.1, guides change weekly-to-monthly while non-guide artifacts (rules, skills, templates, agents) change quarterly-or-less. Companion files pay off where queries are frequent and the narrative is richer than what fits in a frontmatter line. For low-churn artifacts, the same mechanism would be net-negative file proliferation — those use the lighter `last_change_*` frontmatter pattern (DD-95).

**Why not the alternatives** (spec §3.2 enumerates five):

- **Frontmatter array (Option A).** Grows unboundedly inside frontmatter; conflicts with the standing token-economy principle. Frontmatter is for stable schema, not history.
- **Centralized log (Option C).** One file, all artifacts. Loses per-guide locality; merge conflicts; hard to grep for a specific guide's history.
- **SL-only (Option D).** Reuses existing mechanism but query is poor — "why did G7 change in April" requires grepping every SL file.
- **Frontmatter pointer + SL (Option E).** Adopted for non-guide artifacts (DD-95). Insufficient for guides because the per-guide history is already grep-heavy at 11 guides; will worsen.

**Honoring the existing signal.** The empty `extracts/guides/changelog/` directory was created 2026-04-20 by an earlier session that began Phase-1 implementation work without filing the governing DD. This DD ratifies the directory's existence post-hoc and specifies its contents.

**Narrative lives in SL.** The changelog is the per-guide *index* into the SL, not a duplicate of the SL. The Structural line is one or two lines max — anything more belongs in SL where it can be properly threaded with the rest of the session's work.

## Rules for `/synthesize-guide`

1. **Locate or create the changelog file.** Before writing the regenerated guide, the skill checks for `extracts/guides/changelog/<guide-stem>.changelog.md`. If absent, the skill creates it with a minimal title (`# Changelog — <guide title>`) and proceeds to append the first entry.

2. **Construct the entry.** The skill computes the entry from the regen context: trigger-tag (from invocation arg or inferred from re-synthesis cause), finding count + delta, added/removed lists, structural summary (1–2 lines), preservation status (from DD-93 enforcement output), SL link (the session's SL entry path).

3. **Enforce trigger-tag enum.** The skill rejects any trigger-tag not in the closed enum. New tags require a DD amendment.

4. **Enforce line cap.** The skill counts non-header lines. ≤10: write. 11–15: write with warning. >15: abort with structured report.

5. **Append at top.** The new entry is inserted directly after the file's title heading (or at the top of the file if no title heading exists). Most-recent-first ordering is invariant.

## Retroactive Backfill

The 11 currently-staged guides have no changelog entries (they were all synthesized 2026-04-19 before this DD existed). On first re-synthesis after DD-94 lands, each guide gets:

1. **A retroactive stub entry** representing the initial synthesis: `## 2026-04-19 — Session 44 — initial-synthesis` with finding count and an "initial synthesis; no prior version" structural line. SL link points to session-44's SL entry.
2. **The current re-synthesis entry** appended on top of the stub.

Alternative: a one-time backfill IB writes stubs for all 11 guides up front, decoupled from re-synthesis events. Either path is acceptable; the IB-A item (companion to this DD) elects the latter for cleanliness — backfill stubs first, then proceed with normal entries.

The trigger tag `initial-synthesis` is permitted **only** for backfill stubs, not for any future regen. Adding it to the live enum is unnecessary because backfill is one-time.

## Scope and Non-Goals

- **In scope:** All artifacts in `extracts/guides/` subject to `/synthesize-guide`. Future guides automatically. Past guides via retroactive stubs (IB-B).
- **Out of scope:** Non-guide artifacts. Rules, skills, templates, agents use the `last_change_*` frontmatter pattern per DD-95. The companion-file pattern is intentionally guide-only.
- **Out of scope:** Live-location guides. Once a guide deploys from `extracts/guides/` to a live consumer location, the companion changelog stays in `extracts/`. Live-location lifecycle is governed by DD-29 and is out of scope per spec §What This Spec Does NOT Resolve.
- **Out of scope:** Cross-guide diff queries. The companion file enables per-guide history; queries that span guides (e.g., "all G3 + G4 entries this quarter") still grep the changelog directory directly.
