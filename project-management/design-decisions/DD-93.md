# DD-93

> **For agents:** When `/synthesize-guide` re-synthesizes an existing guide, two surfaces are preserved verbatim: the canonical `## Nick's Annotations` section, and any block bounded by `<!-- PRESERVE -->` … `<!-- /PRESERVE -->` HTML comments. A post-regen regression test diffs preserved content; if any drift is detected, the write aborts.

---

## The Constraint

Two preservation surfaces, both authoritative:

1. **Canonical named section.** Every guide may carry a `## Nick's Annotations` section. `/synthesize-guide` reads its contents pre-regen and re-emits them verbatim post-regen. Position in the regenerated body is preserved (skill writes the section back at its original ordinal location, or at the tail if absent in the new structural template).

2. **Marked regions.** Any block in a guide bounded by `<!-- PRESERVE -->` … `<!-- /PRESERVE -->` HTML comments is preserved verbatim — anywhere in the guide, including mid-section. Multiple marked regions are supported. Regions are identified by their line position relative to surrounding generated structure; the skill writes them back at the closest semantically equivalent location in the regenerated body.

**Enforcement — post-regen regression test:**

- Pre-regen: skill captures byte-content of all preserved surfaces (the named section's body + every marked-region body).
- Post-regen: skill re-extracts the preserved surfaces from its candidate output.
- Diff: byte-equality required across all preserved content.
- On drift: the skill **aborts the write** (fails closed) and surfaces a structured drift report — which preserved surface drifted, the offending diff, and the recommended fix path.

A guide with no preserved sections has unchanged regen behavior — the rule is a no-op.

## Why

Guides are the highest-churn artifact class (spec §4.1, "Low stability"). The current `/synthesize-guide` behavior is full-regenerate: every staleness cycle, dimension rebalance, or Nick-requested re-synthesis overwrites the guide body entirely. Any human edits Nick lands in a guide between syntheses are silently clobbered.

The loss is invisible. The next reader sees a coherent regenerated guide; they cannot tell that prior tuning was lost. Git log captures the file diff but not the semantic intent of the human edit.

Two real triggers for this risk are already on the queue:
- G7 is overdue for re-synthesis (+11 findings since last).
- G2 / G9 will follow once Phase-1 unblocks them.

Without preservation, every re-synthesis is a forcing function for Nick to either (a) skip the regen, or (b) accept the clobber. Both are bad. Preservation makes regen safe.

The dual-surface approach (named section + comment markers) handles two distinct human-edit shapes:
- **Standing annotations** — Nick's framing, emphasis, or amplifications added across the guide's lifetime. Belong in `## Nick's Annotations`.
- **In-section tuning** — a tightened paragraph in Pitfalls, a sharpened example in Step 4. Belong inline, marked with `<!-- PRESERVE -->`.

Forcing all human edits into one shape would either (a) push standing annotations into mid-body comment blocks (discoverability loss), or (b) require Nick to extract every in-section tweak into a separate Annotations entry (workflow friction).

## Rules for `/synthesize-guide`

1. **Detect.** Before regenerating, parse the existing guide. Capture: (a) the body of any `## Nick's Annotations` section; (b) the body of every `<!-- PRESERVE -->` … `<!-- /PRESERVE -->` region in document order.

2. **Preserve.** Generate the structural body from `source_findings[]` per the existing skill procedure. Then re-insert the preserved content at the corresponding positions in the candidate output.

3. **Regenerate the rest.** All non-preserved content is fully regenerated. The skill never partially-regenerates the structural body — preservation does not compose with merge-diff.

4. **Diff-check (regression test).** Re-extract the preserved surfaces from the candidate output. Compare byte-for-byte against the captured pre-regen content. Any non-identity is a regression.

5. **Fail closed on drift.** If the diff-check fails, the skill does NOT write the candidate output. It emits a structured drift report (which surface, the offending diff, recommended remediation) and exits non-zero. Nick re-runs after fixing the skill-side bug.

## Acceptance Criteria

| Test | Expected |
|---|---|
| Guide has `## Nick's Annotations` with body content; re-synthesize | Section body byte-identical post-regen. Section preserved at its ordinal location (or appended if structural template no longer reserves a slot). |
| Guide has `<!-- PRESERVE -->` region mid-Pitfalls; re-synthesize | Region preserved verbatim. Surrounding Pitfalls content fully regenerated. |
| Guide has multiple marked regions across distinct sections; re-synthesize | All regions preserved verbatim, in original document order. |
| Guide has no preserved surfaces; re-synthesize | Behavior unchanged from current full-regenerate. |
| Skill bug causes preserved-section drift in candidate output | Write aborts. Drift report emitted. No file change committed. |

## Scope and Non-Goals

- **In scope:** All artifacts in `extracts/guides/` that are subject to `/synthesize-guide`. Both pre-existing guides (which have no preserved surfaces yet — the rule is a no-op until Nick adds one) and future guides.
- **Out of scope:** Non-guide artifacts (rules, skills, templates, agents) — those are governed by drift-detection-and-flag (Phase 2) and `last_change_*` frontmatter (DD-95). Preservation is guide-specific because guides are the only class with full-body regenerate semantics.
- **Out of scope:** Merge-diff machinery (Option B in spec §1.2). Preservation is the intentionally-cheaper alternative; merge-diff is not on the roadmap.
- **Out of scope:** Auto-detection of "edit-worthy" content. The skill preserves only what is explicitly marked. Implicit human edits (anywhere outside the named section / comment markers) are NOT preserved — they are still clobbered. This is by design: explicit markers force a discipline that makes regen behavior predictable.
