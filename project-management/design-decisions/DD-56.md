# DD-56

> **Amended by DD-103 (2026-06-18).** The `Cross-System → systems/meta-system/...` routing row folds into the engine: both `target_system: Cross-System` and `target_system: Improvement Loop` resolve to `systems/improvement-loop/project-management/implementation-backlog/`. Archived systems keep their IB folders as read-only history; numbers stay globally unique. DD stays Binding for the system-scoped distribution pattern.

> **For agents:** DD-56 tells you where Implementation Backlog items live. They are NOT in a single root-level folder. Each system has its own `project-management/implementation-backlog/` folder. Use the path map below to find IB items by system scope.

---

## Core Decision

Implementation Backlog items are distributed from a single root-level `implementation-backlog/` folder to system-scoped `project-management/implementation-backlog/` folders. This enforces boundary isolation — a Claude Build agent cannot see Household OS backlog items, and vice versa. This follows the same pattern established by DD-55 for Design Decisions.

[Updated 2026-04-05: S1+S2 merged into Household OS per DD-58]

### Resolution Pattern

To find a specific IB item by number, glob across all locations:
```bash
find . -path '*/project-management/implementation-backlog/IB-{NNN}.md' -print -quit
```

To count all IB items:
```bash
find . -path '*/project-management/implementation-backlog/IB-*.md' | wc -l
```

### Rationale

- **Boundary isolation:** System-scoped agents should only access their own backlog
- **Fractal consistency:** IB items now live inside the fractal unit's `project-management/` folder, consistent with DD-52 and the DD-55 precedent
- **Scalability:** New systems automatically get their own IB namespace
