# DD-52

> **Amended by DD-103 (2026-06-18).** The 7-folder fractal still governs the engine. Two updates: (1) the **charter is a deliberate root-level exception** — `CHARTER.md` sits at the workspace root, not inside any unit's `governance/`, because it scopes the whole workspace (see DD-105); (2) the body example "`meta-system/`" is now historical — that unit dissolved into the engine. DD stays Binding.

> **For agents:** DD-52 defines the standard directory structure for every unit in MetaSystem. When creating a new system or project, scaffold all 7 fractal folders. When looking for content, navigate by folder role — every unit organizes knowledge, agents, and operations the same way.

---

## Core Decision

A predictable, self-similar structure at every level of MetaSystem. The same 7 folders appear whether you're looking at meta-system/, incubator/claude-build/, or incubator/my-project/. Agents know where to find things without unit-specific instructions.

The fractal pattern serves the goal of producing robust, production-ready code with a small surface area. Every supporting folder (governance, knowledge, agents, project-management, operations) exists to make the product in app/ better.

---

## The 7 Folders

| Folder | Purpose |
|--------|---------|
| **app/** | The product — source code, configs, deployments |
| **governance/** | Rules, constraints, applicable DDs |
| **knowledge/** | Patterns, guides, templates, reference |
| **agents/** | The agentic layer — team members with skills, workflows, hooks, and agent-private `reflections/` subfolders for self-assessment (see DD-91) |
| **project-management/** | Requirements, milestones, progress |
| **operations/** | Error tracking, events, lessons, logs |
| **archive/** | Completed/retired work |

## Knowledge Subdirectories

| Directory | Contains |
|-----------|----------|
| **patterns/** | Reusable approaches — what to do |
| **guides/** | How-to documentation and playbooks |
| **templates/** | Scaffolding for this unit's artifacts |
| **reference/** | Active read-only context material |

---

## Engine Directory Coexistence

Some fractal folders coexist with tool-specific engine directories:

| Fractal folder | Engine directory | Relationship |
|---------------|-----------------|--------------|
| agents/ | .claude/agents/ | Fractal holds full context; engine holds harness definitions |
| project-management/ | .planning/ | Fractal is the standard view; .planning/ is the GSD engine |
| governance/ | .claude/rules/ | Fractal holds human-readable docs; engine holds rule files |
