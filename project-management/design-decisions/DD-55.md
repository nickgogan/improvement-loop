> **Amended by DD-103 (2026-06-18).** The `Cross-System → systems/meta-system/...` routing row folds into the engine: both `target_system: Cross-System` and `target_system: Improvement Loop` resolve to `systems/improvement-loop/project-management/design-decisions/`. Archived systems (`archive/household-os/`, `archive/claude-build/`, `archive/meta-system/`) keep their DD folders as read-only history; numbers stay globally unique. The boundary-isolation rationale is moot with one live system. DD stays Binding for the system-scoped distribution pattern.

> **For agents:** DD-55 tells you where Design Decisions live. They are NOT in a single root-level folder. Each system has its own `project-management/design-decisions/` folder. Use the path map below to find DDs by system scope.

## Core Decision

Design Decisions are distributed from a single root-level `design-decisions/` folder to system-scoped `project-management/design-decisions/` folders. This enforces boundary isolation — a Claude Build agent cannot see Household OS governance, and vice versa.

[Updated 2026-04-05: S1+S2 merged into Household OS per DD-58]

### Resolution Pattern

To find a specific DD by number, glob across all locations:
```bash
find . -path '*/project-management/design-decisions/DD-{NN}.md' -print -quit
```

To count all DDs:
```bash
find . -path '*/project-management/design-decisions/DD-*.md' | wc -l
```

### Rationale

- **Boundary isolation:** System-scoped agents should only access their own governance
- **Fractal consistency:** DDs now live inside the fractal unit's `project-management/` folder, consistent with DD-52
- **Scalability:** New systems automatically get their own DD namespace
