# DD-89

> **For agents:** IL has four zones for design-and-governance artifacts. Shape determines placement. Deliberative specifications (audits, contracts, registries, rubrics, lifecycle specs, tracking-mechanism specs) → `project-management/design-notes/`. Agent-initiated proposals (from `/solicit-proposals` rounds or ad-hoc) → `governance/proposals/`. Ratified rules → `governance/` root. Runtime event output (SL entries, handoffs, reports) → `operations/`. `operations/design-notes/` does not exist.

## The Constraint

The IL fractal separates design-and-governance artifacts into four zones. Each has a distinct purpose, lifecycle, audience, and authority.

| Zone | Purpose | Contains | Governance |
|---|---|---|---|
| `project-management/design-notes/` | Deliberative specifications | Substrate audits, read contracts, use-case registries, acceptance rubrics, lifecycle specs, spot-checks, tracking-mechanism specs, pipeline-mechanics specs | Owner-governed; any agent may write |
| `governance/proposals/` | Agent-initiated proposals (Proposal-First tier) | Output from `/solicit-proposals` rounds and ad-hoc agent-initiated proposals (per DD-91) | Agents author; Owner curates; Nick gates |
| `governance/` (root) | Ratified governance rules | `boundary-rules.md`, `pipeline-rules.md`, `agent-rules.md`, `knowledge-rules.md` | Owner maintains, derived from MetaSystem constitution |
| `operations/` | Runtime event output only | SL entries, handoffs, research-reports, loop-reports, identification reports, extraction reports | Any agent, event-driven |

### Placement rule

**Artifact shape governs placement; author role is a heuristic, not authority.**

- Deliberative specification → `project-management/design-notes/`
- Ratified governance rule → `governance/` root
- Runtime event output → `operations/`
- Agent-initiated proposal → `governance/proposals/`

**Owner + Nick collaborative governance work** goes directly into DDs (new or amended); it does not pass through `governance/proposals/`.

### Deprecations

- `operations/design-notes/` is deprecated and removed. Its seven files were migrated to `project-management/design-notes/` on 2026-04-22; all cross-references were updated.

## Why

The fractal pattern (DD-52) already separates `governance/`, `project-management/`, and `operations/` with distinct lifecycles — what's ratified vs what's being decided vs what happened. Design artifacts had accumulated in `operations/design-notes/` by convenience, violating the split. Codifier design notes (substrate audits, contracts, lifecycle specs) are deliberative specifications, not runtime events. This DD makes the fractal distinction operative for design artifacts.

Two pains resolved:
1. Owner queries for "current system-wide rules" no longer scan a folder full of sessional descriptive output.
2. Codifier queries for "how does the substrate audit relate to the pipeline collapse proposal?" no longer wade through handoffs and SL entries.
