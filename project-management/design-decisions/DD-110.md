# DD-110

> **For agents:** Two different audits, two homes, one parent. `/audit-artifacts` (was
> `/audit-system`) audits a system **by assessing each artifact** against its contract → writes to
> `<target>/operations/artifact-audits/<date>/`. `/system-audit` checks **IL internal consistency /
> drift** → writes to `operations/system-audits/{date}-system-audit.md`. The root `audit-reports/`
> folder is gone; both audit homes are under `operations/`.

---

## Core Decision

Session-122's audit (IB-169) surfaced two audit-report destinations that read as accidental:
`/audit-system` wrote to a root-level `audit-reports/`, while `/system-audit` wrote to
`operations/audit-reports/` — two folders named "audit-reports," plus two skills whose names are
near-anagrams (`audit-system` vs `system-audit`). Verification confirmed the two operations are
**genuinely distinct** (different unit, lens, and reusability), so the fix is **disambiguation, not
consolidation**:

| | `/audit-artifacts` (was `/audit-system`) | `/system-audit` (unchanged) |
|---|---|---|
| **Question** | Is each *artifact* well-formed vs. its contract? | Has *the system* drifted / is it self-consistent? |
| **Unit** | Per-artifact (composes `/assess-*`) | Per-surface (9 inspection categories) |
| **Reusable** | Generic — any system | IL-only, bespoke |
| **Altitude** | Top (DD-104 composition layer) | Owner system-health pass (DD-86) |
| **Home (new)** | `<target>/operations/artifact-audits/<date>/` | `operations/system-audits/{date}-system-audit.md` |

Three changes:

1. **Rename the generic skill** `/audit-system` → `/audit-artifacts`. Only one skill is renamed — that
   breaks the anagram; `/system-audit` is already well-named and pairs with `/system-health`.
2. **Both homes under `operations/`** with lens-distinct names (`artifact-audits/`, `system-audits/`).
   The root-level `audit-reports/` is removed (existing run history moved, history preserved via
   `git mv`).
3. **Output contract:** `/audit-artifacts` always writes under `<target>/operations/` (creating
   `operations/` if the target lacks it), replacing the prior `<target>/audit-reports/` default.

## Why

- The split was a naming collision, not a redundancy — consolidating the two reports into one folder
  (IB-169 options b/c) would re-mix two different report shapes. Distinct names resolve the confusion
  while keeping both reports.
- `operations/` is the engine's designated home for generated run data ("loop reports, handoffs,
  system log, audit reports"); `docs/` is for authored documentation, so audit output belongs in
  `operations/`. Moving the artifact-audit home off the IL root also declutters the root.
- Renaming only `/audit-system` (not `/system-audit`) is the minimum change that kills the anagram —
  Rule 11: symmetry is not a reason to rename both.

## What this does NOT change

- It does **not** change what either skill *does* — only their names/output paths.
- It does **not** consolidate the two reports into one artifact; they remain distinct outputs.
- It does **not** rewrite immutable prior DDs (DD-103, DD-104, DD-107) that reference `/audit-system`
  — those references denote the skill **now named `/audit-artifacts`**. The dated v1 design-contract
  (`design-notes/2026-06-12-audit-system-design-contract.md`) is preserved as a historical record
  with a `superseded_in_part_by: DD-110` banner.
