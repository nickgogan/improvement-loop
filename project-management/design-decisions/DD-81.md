# DD-81

> **For agents:** Pattern-classified findings do NOT go through `/extract-artifacts`. They route to `/synthesize-guide`, which produces end-directed guides with embedded templates and prompt scaffolds. `/extract-artifacts` handles only rules, skills, templates, and agents — forms that are directly deployable.

---

## The Decision

The pipeline from DD-80 splits by form after identification:

```
                                         ┌─ rules/skills/templates/agents ─→ /extract-artifacts ─→ deploy
Finding → /identify-artifacts → Report → [Nick reviews]
                                         └─ patterns ─────────────────────→ /synthesize-guide ──→ deploy
```

**What changes:**

1. `/extract-artifacts` adds a pattern-skip filter. When processing an identification report, pattern-classified findings are logged as "routed to guide synthesis" and skipped. Only non-pattern forms (rules, skills, templates, agents) are drafted and written.
2. `/synthesize-guide` (IB-146, promoted to P1) consumes pattern findings directly from `research-findings/` and produces guide artifacts in `extracts/guides/`. Guides are end-directed playbooks that synthesize multiple related findings into actionable procedures with embedded templates and prompt scaffolds.
3. The 70 pattern artifacts produced during the initial extraction run (2026-04-19) remain in `extracts/patterns/` as reference material. They are not a pipeline stage — they can inform guide authoring but are not the product.

**What does NOT change:**

- **Form Router and `/identify-artifacts`:** Classification is unchanged. The Router still classifies every finding into one of 5 forms (pattern/skill/rule/template/agent). The form determines routing, not output format.
- **Human gates (DD-29):** Preserved at both stage boundaries — after identification and after guide/artifact drafting.
- **ContractSpec (DD-78):** Guides carry ContractSpec, same as extracted artifacts.
- **Non-pattern extraction:** Rules, skills, templates, agents still follow the DD-80 extraction path. Proved working in the session 25 production run (3 rules, 1 skill, 1 template extracted successfully).

## Why

Session 25's extraction run revealed that pattern artifacts are reformatted findings — they restructure the finding body into Problem/Forces/Solution/Consequences and add ContractSpec, but they don't produce something a practitioner can paste into a project. A pattern describing "how to structure agent context" is analytically useful but not actionable. The consumer needs a guide that says "here's how to write an agent context file, here's a template, here's an example."

The key insight: **patterns are compositional primitives; guides are end-directed products.** The IL's goal is to produce guidance and reusable assets for agentic development. Patterns describe design shapes; guides synthesize those shapes into procedures with embedded templates. The extraction step adds structure (ContractSpec, Problem/Forces) but not usability for the 92% of findings that are patterns.

Non-pattern forms (rules, skills, templates, agents) ARE directly deployable — a rule goes to `.claude/rules/`, a template gets rendered. The extraction step adds genuine value for these forms. The split preserves that value while eliminating the intermediate pattern layer.
