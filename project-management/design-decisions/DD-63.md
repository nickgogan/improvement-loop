# DD-63

> **For agents:** DD-63 defines how you communicate with other agents. You do NOT message other agents directly. You read upstream artifacts (markdown files) as context and write downstream artifacts as output. Never modify another agent's artifact — if you disagree, escalate through the defined chain.

---

## Core Decision

All inter-agent communication is mediated through shared state — structured artifacts each agent produces. Agents do not communicate directly with each other.

### The Artifact Chain

```
Human idea
  → PO produces PRD
    → Architect produces Architecture Doc + ADRs
      → TPM produces Task List + Milestone Definitions
        → Engineer(s) produce Code + Tests + Implementation Notes
          → Tester produces Test Results + Bug Reports
            → TPM verifies task completion
              → Architect verifies architectural compliance
                → PO verifies acceptance criteria
                  → Human Gate
```

Each artifact is a markdown file in the project's directory structure. Agents read upstream artifacts as context and write downstream artifacts as output.

### Communication Rules

1. **No direct messaging.** Agents do not talk to each other. They read and write artifacts.
2. **No cross-modification.** No agent modifies another agent's artifact without an explicit escalation event.
3. **Escalation chain:** Engineer → TPM → Architect → PO → Human. Each level handles what it can and escalates what it can't.
4. **Structured output.** Agents produce complete, structured artifacts — not conversational fragments.
5. **Audit trail.** The system log (operations/system-log/) captures milestone outcomes, human gate decisions, and escalation events. It is the audit trail, not the communication channel.

### Communication Medium

**Current:** Markdown files in the project's directory structure, managed as part of the Obsidian vault.

**Future:** Designed for migration to a real database (e.g., MongoDB) when the volume and query complexity outgrows flat files. The artifact schema should be database-ready from day one (structured frontmatter, typed fields).

**Not Notion.** Notion MCP is reserved for Household OS runtime operations only. Agent communication for incubator and systems-level work uses the local-first artifact model.

### Relationship to IL Pipeline

DD-35 established the artifact-chain pattern for the Improvement Loop:
```
Researcher → [Findings DB] → Proposer → [Proposals DB] → Evaluator → Enhancer → [Deploy]
```

DD-63 generalizes this pattern to all agent team work. The principle is the same — database-mediated (or artifact-mediated) communication with strict read/write boundaries per role.
