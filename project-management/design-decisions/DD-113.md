# DD-113

> **For agents:** DD<->IB linkage lives in ONE place — `source_dd` (a YAML list) on the IB item. There is no `ib_items` field on DDs anymore. To find a DD's backlog items, query `source_dd` across IB files (`rg -l 'DD-X'` on the source_dd blocks, or `/ib --dd DD-X`). Never reintroduce a reverse list on DDs — it drifts from the authored forward link.

## Problem

Two fields encoded the same DD<->IB relationship in opposite directions, each hand-maintained:
- `source_dd` (forward, on IB items) — well-populated but stored as scalar/comma-strings, violating the schema's own `array[string]` declaration.
- `ib_items` (reverse, on DDs) — sparsely populated; normalized to YAML lists in session 126, leaving the schema's `string | null` comment stale.

Independent hand-maintenance had already diverged: IB-147 and IB-146 declared `source_dd: "DD-45"` while DD-77/DD-80 (IB-147) and DD-81 (IB-146) claimed them in reverse — the forward scalar pointing at the wrong DD. Multi-DD relationships were under-captured by the scalar forward link.

## Decision rationale

- **One authored direction eliminates divergence structurally.** With only `source_dd` authored, there is no second direction to drift against.
- **source_dd was already de-facto multi-valued** (comma-strings on IB-96/106/123/124/138) and the schema already declared it `array[string]` — so formalizing it as a list conforms data to the existing schema rather than inventing a new model.
- **Reverse capability is preserved, not lost.** A query (`rg` on source_dd, or an `/ib --dd` filter) reconstructs the reverse view on demand. This honors the session-126 decline of full `ib_items` retirement — the relationship survives; only the redundant stored field is removed.
- **Aligns with standing principles:** no content requiring per-session updates (a denormalized reverse cache is exactly that); abstractions earn their keep (a one-line query replaces a hand-maintained field).

## Scope of execution (session 127)

- `source_dd` rewritten to YAML-list form across all IB items (single values become one-item lists; comma-strings split; nulls preserved).
- 4 non-lossy reconciliations folding prior reverse claims into the forward link (IB-142, IB-146, IB-147, IB-170).
- `ib_items` field removed from all DD frontmatter.
- `_schema.yaml` updated: `source_dd` documented as the SSOT; `ib_items` removed with a do-not-reintroduce note.
