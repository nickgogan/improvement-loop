# DD-77

> **For agents:** Router picks one form, full stop. Never add `secondary_form`, `pending_forms`, or co-occurrence metadata to FormAssignment. If you see a pattern that implies a rule, codify the pattern — the rule is harvested later.

---

## The Constraint

The Form Router classifies each ResearchFinding into exactly one `assigned_form` from the 5-form taxonomy: `pattern | skill | rule | template | agent`.

**What is NOT in the Router's output:**
- `secondary_form` or `secondary_form_hints`
- Co-occurrence flags ("this finding is also a rule")
- Pending-edge metadata for future harvesting
- Forward-looking harvest backlog entries

**How co-occurrence is handled:**
- The Router picks the center of gravity (primary form)
- `/extract-artifacts` (IB-147) — if built — scans codified artifact bodies for harvestable secondary content
- System owners reading a codified pattern can independently decide to codify a derived rule

This is a negative design decision: it explicitly prohibits a feature (secondary-form flagging) that was considered and rejected.

## Why

Forward-flagging creates maintenance edges that go stale with primary artifact drift. Same failure mode as cross-finding prerequisite tracking (killed in session 20). The calibration set (session 22) confirmed co-occurrence in 10 of 50 findings (6 rule co-occurrences, 4 template co-occurrences) — all resolved cleanly by picking the primary form and noting the co-occurrence for downstream harvesting.

The `/extract-artifacts` approach is structurally superior: it operates on codified artifacts (which are current) rather than Router metadata (which is frozen at classification time).
