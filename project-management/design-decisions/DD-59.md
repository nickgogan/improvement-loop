# DD-59

> **Amended by DD-103 (2026-06-18).** The `Cross-System → systems/meta-system/...` routing row folds into the engine: both `target_system: Cross-System` and `target_system: Improvement Loop` resolve to `systems/improvement-loop/operations/system-log/`. Archived systems keep their system-log folders as read-only history. DD stays Binding for the system-scoped distribution pattern.

> **For agents:** DD-59 tells you where System Log entries live. They are NOT in a single root-level folder. Each system has its own `operations/system-log/` folder. Use the path map below to find entries by system scope.

---

## Core Decision

System Log entries are distributed from a single root-level `system-log/` folder to system-scoped `operations/system-log/` folders. This completes the distribution pattern established by DD-55 (DDs) and DD-56 (IB items) — all three governance databases now follow the same system-scoped pattern.

### SL Path Map

| target_system | Location | Count |
|---------------|----------|-------|
| Household OS | `incubator/household-os/operations/system-log/` | 22 |
| Claude Build | `incubator/claude-build/operations/system-log/` | 4 |
| Improvement Loop | `systems/improvement-loop/operations/system-log/` | 1 |
| Cross-System | `systems/meta-system/operations/system-log/` | 24 (including this change's log entry) |

### Resolution Pattern

To find a specific log entry by name, glob across all locations:
```bash
find . -path '*/operations/system-log/*{query}*.md' -print
```

To count all entries:
```bash
find . -path '*/operations/system-log/*.md' | wc -l
```

### Rationale

- **Consistency:** Completes the DD-55/DD-56 pattern — all governance databases are now system-scoped
- **Fractal alignment:** Log entries now live inside the fractal unit's `operations/` folder, consistent with DD-52
- **Boundary isolation:** System-scoped agents access only their own operational history
- **No root governance data:** With this change, no governance databases remain at workspace root
