# DD-69

> **For agents:** DD-69 requires bidirectional linkage between sources and findings. When creating or updating either, always update both sides. A source with zero findings or a finding with zero sources is a defect — use `/linkage-repair` to fix.

---

## The Constraint

The research KB maintains a **bidirectional linkage invariant** between sources and findings:

| Direction | Field | Location | Requirement |
|-----------|-------|----------|-------------|
| Source → Findings | `linked_findings:` (frontmatter array) | `research-sources/*.md` | Every source must list the finding filenames it contributed to |
| Finding → Sources | `sources:` (frontmatter array) | `research-findings/*.md` | Every finding must list the source filenames it was extracted from |

## What Constitutes a Defect

- A source with an empty `linked_findings` array (zero findings extracted)
- A finding with an empty `sources` array (no provenance)
- A source that lists a finding, but the finding doesn't list the source back (or vice versa)

## Why This Matters

The source quality audit (2026-04-07) found that 32 of 74 sources (43%) had zero linked findings — 20 of which were High relevance. This wasn't a content gap; it was a linkage gap. Findings existed but weren't cross-referenced to their sources. Without bidirectional links:
- Source ROI is invisible (can't tell which sources produced value)
- Finding provenance is untraceable (can't verify claims)
- Triage decisions have no feedback signal (can't learn which source types are most productive)

## Enforcement

- **During extraction:** When creating a finding, add the source filename to `sources:`. When linking a finding, add the finding filename to the source's `linked_findings:`.
- **After bulk operations:** Run `/linkage-repair` to detect and fix broken links.
- **Audit cadence:** Source quality audits should check linkage integrity as a first-class metric.
