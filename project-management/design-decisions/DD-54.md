# DD-54

> **For agents:** DD-54 means every content file you create must have YAML frontmatter per `_schema.yaml` at the workspace root. Use controlled vocabularies for type, category, target_system, stage, and author fields. This enables Dataview queries in Obsidian and future MongoDB backing.

---

## Core Decision

MetaSystem/ is a single Obsidian vault. All markdown content files (except CLAUDE.md, _index.md catalogs, and .template files) carry standardized YAML frontmatter.

### Frontmatter Schema

Defined in `_schema.yaml` at workspace root:

| Field | Type | Controlled Vocabulary? |
|-------|------|----------------------|
| title | string | No |
| id | string (kebab-case, unique) | No |
| type | string | Yes: pattern, guideline, governance, resource, template-doc |
| category | string | Yes: agent-design, skill-design, knowledge-flow, project-lifecycle, schema-change, review-process, governance |
| target_system | array[string] | Yes: s1-schema, s2-operations, claude-build, s4-bootstrap, improvement-loop, cross-system |
| stage | string | Yes: draft, active, deprecated |
| created | date (ISO 8601) | No |
| updated | date (ISO 8601) | No |
| author | string | Yes: nick, jr, claude, improvement-loop |
| source_dd | array[string] | Pattern: DD-\d+ |
| source_ib | array[string] | Pattern: IB-\d+ |
| tags | array[string] | No (freeform) |
| aliases | array[string] | No |
| _provenance | object | Only for migrated Notion docs |

### Three Consumers, One Schema

| Consumer | Interface | Query Method |
|----------|-----------|-------------|
| Nick | Obsidian app | Dataview plugin, graph view, search |
| JR | Git browse or Obsidian Publish | File navigation, search |
| Agents | File reads | Glob/Grep/Read tools, frontmatter parsing |

---

## Obsidian Configuration

- `.obsidian/` at workspace root (not per-system)
- Plugins: Dataview (frontmatter queries), Templater (note creation)
- `.obsidian/workspace.json` in `.gitignore` (changes every open)
- Graph view colored by path (governance, knowledge, claude-build, etc.)

---

## MongoDB Readiness

All frontmatter fields are typed for direct MongoDB insertion:
- File path becomes `_path` field
- Markdown body becomes `_content` field
- Controlled vocabulary fields use indexed enums
- The `_provenance` prefix signals non-queryable metadata
