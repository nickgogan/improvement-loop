# DD-117

> **For agents:** Every non-guide extract (rule, skill, template, agent) carries two frontmatter fields: `last_change_session` (the session number of the most recent change) and `last_change_report` (the filename stem of the report or queue file that authorized that change). `/extract-artifacts` writes both on every create or update. `last_change_sl` is retired for new writes; existing values are frozen historical pointers. Guides still use companion changelog files (DD-94).

---

## The Constraint

```yaml
last_change_session: 140
last_change_report: "2026-07-12-identification-report"
```

**Field semantics:**

- `last_change_session` — **integer**. Unchanged from DD-95: the session number of the most recent regen, drift-update, or Nick-edit that landed in this artifact. Overwritten on every write. Resolved from `--session NN` (prompt if missing; abort under `--auto`).

- `last_change_report` — **string**. The bare filename stem (no path, no `.md`) of the run's **authorizing input**:
  - **Report mode** (`<report-filename>` / `--latest`): the identification report stem in `operations/pattern-identification-reports/`.
  - **Harvest mode** (`--harvest-row`): the harvest-queue file stem in `extracts/guides/` (e.g., `g7-context-engineering.harvest-queue`); the queue-row footer carries the row-level specifics.
  - **Update mode** (`--update` — post-drift-report ruling, Nick-requested re-extraction, dimension-rebalance regen): the identification report driving the re-extraction run.

**Derivation, not input.** The anchor is derived from the input the skill already requires — there is no separate argument to pass, no prompt, and no existence check beyond the one the run already performs on its own input. The `--sl STEM` argument, its prompt/abort paths, and the SL existence validation are removed from `/extract-artifacts`.

**No backfill.** Existing artifacts carrying `last_change_sl` keep it as a valid read-only pointer into the frozen SL corpus (`operations/system-log/`, historical per the DD-59 scope note). On the artifact's next write, `last_change_sl` is removed and `last_change_report` is written. A corpus-wide rename would churn ~26 files to update pointers that still resolve — not worth it (token economy).

## Why

DD-95 anchored artifact provenance to System Log entries and made a missing SL entry a **write-abort**. DD-116 retired the SL as a producer (session 138): no new SL entries exist to point at, so every future non-guide artifact write aborts — the skill was functionally broken (substrate audit, Urgent #1). Nick ruled the new anchor is the identification report (session 139, door-type delegation).

The report is a *better* anchor than the SL entry was:

- **It answers the same question.** "Where do I read the why?" — the identification report carries the classification rationale, confidence, and Nick's approval for exactly the findings written in that run. The SL entry only narrated the session around it.
- **It already exists at write time by construction.** The report is the skill's required input, so the pointer can never be broken at write — the validation that DD-95 had to bolt on becomes structural.
- **It was already being written.** The artifact template has carried an `identification_report` field since DD-80; this DD makes the *lifecycle* pointer consistent with it. (`identification_report` records the report of the original extraction and is preserved on update; `last_change_report` records the report of the most recent change and is overwritten — same split as DD-95's session/SL pair.)

## Rules for `/extract-artifacts`

1. **Write on create.** Both fields populated: `last_change_session` from `--session`; `last_change_report` derived from the run's authorizing input per the mode table above.
2. **Write on update.** Both fields overwritten with the current run's values. If the existing artifact carries `last_change_sl`, remove it in the same write.
3. **No SL argument.** `--sl` is not accepted. The report anchor is never prompted for.
4. **Abort on missing session number.** Unchanged from DD-95.

## Schema Update

`_schema.yaml` §Lifecycle Tracking: `last_change_sl` is marked historical (valid on artifacts last written before this DD; never written anew); `last_change_report` is added with the semantics above.
