# DD-66

> **For agents:** DD-66 governs how MetaSystem evaluates and adopts capabilities from external agentic tooling packages. Use the spectrum to classify each dependency. Never clone external repos into the vault.

---

## The Constraint

When MetaSystem adopts capabilities from external packages (GSD, gstack, BMAT, Mem Zero, Open Claude, or any future tooling), the adoption must be classified on a three-position spectrum:

| Position | What It Means | When to Use |
|----------|--------------|-------------|
| **Full cherry-pick** | Extract the pattern, rewrite for MetaSystem's context. We own it entirely. | Our governance constraints differ fundamentally from the package's assumptions. |
| **Thin wrapper** (default) | Use the package, overlay our governance and configuration. Bounded maintenance. | The package is 80%+ right and our additions are configuration, not redesign. |
| **Wholesale adoption** | Use as-is, accept its opinions. | The package's opinions are our opinions, or we don't need an opinion. |

**The default position is thin wrapper** unless there is a specific reason to go left (cherry-pick) or right (wholesale).

## Upstream Tracking

External projects are tracked via a **metadata registry** at `systems/improvement-loop/watched-libraries/`, not by cloning repos into the workspace.

Each registry entry records:
- What we use from the project and where it sits on the spectrum
- Which local patterns, skills, or configs derive from it
- Last evaluated version and change summary

**Repo clones are prohibited in the vault.** Rationale:
- Obsidian indexes all `.md` files — external repos pollute graph view, search, and Dataview queries (violates DD-54)
- Git-in-git or submodules create maintenance friction (violates DD-51's single-repo model)
- The code itself is not needed for triage — changelogs and release notes suffice

When upstream changes are detected, triage depends on spectrum position:
- Cherry-pick: "Does this invalidate our version of the pattern?"
- Thin wrapper: "Does our wrapper need updating?"
- Wholesale: "Is this a breaking change we need to absorb?"

## Rationale

Nick and JR are two people. External packages have advantages MetaSystem can't replicate: more users testing, dedicated maintainers, focused scope, and automatic upgradability. Cherry-picking everything means maintaining a parallel ecosystem. Adopting everything means losing governance control. The thin-wrapper default balances both — upstream upgrades flow through with bounded blast radius, while MetaSystem's constitutional constraints (DDs, fractal pattern, governance layer) remain intact.
