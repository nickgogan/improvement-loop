# DD-74

> **For agents:** DD-74 governs context file hygiene. Never put counts, directory listings, or reference data that can be derived from the codebase into CLAUDE.md, rules, or skills files. Use "see X for details" pointers instead. Keep CLAUDE.md under 100 lines. Frontmatter on individual artifacts is the source of truth — most `_index.md` catalogs were removed during the session-61 cleanup sweep.

---

## The Constraint

Context files — any file automatically loaded into agent context on session start — are governed by the following token budget rules:

### Line Limits

- **CLAUDE.md files** must stay under **100 lines**. If a CLAUDE.md exceeds this, it must be refactored (move detail into on-demand files, replace inlined data with pointers).

### No Hardcoded Counts

- Never write counts of DDs, IB items, findings, sources, or other entries into prose or tables.
- Counts drift immediately and require per-session maintenance to stay accurate.
- If a count is needed, agents should compute it on demand via Glob or Grep.

### No Duplicated Derivable Content

- Content that can be derived by reading the codebase — file paths, directory listings, current counts, entry catalogs — must **not** be duplicated in context files.
- Prefer **on-demand pointers**: "see `systems/meta-system/governance/` for details" over inlined copies of that content.

### Frontmatter Is the Source of Truth (amended 2026-04-23)

- The **frontmatter on each artifact** (DD, IB item, finding, source, authority) is the authoritative record of its state.
- `_index.md` catalogs are **not maintained** for most governance folders — they were removed during the session-61 cleanup sweep because ledger-style catalogs drift between sessions and duplicate frontmatter.
- The only `_index.md` files that remain fall into two groups: **Dataview-driven live views** (watched-libraries, knowledge/patterns, knowledge/guides, etc.) where Obsidian computes the contents on demand, and **load-bearing substrate maps** (governance narratives, Librarian reference layer) where the file is mostly prose, not a row catalog.
- Discovery mechanism: ripgrep / Glob on frontmatter, or the `/track`, `/dd`, `/ib`, `/sl` skills. Never require a catalog update as part of a workflow step.

**Amendment history:** This section originally read "_index.md Is Not Blocking" and treated catalog updates as optional-at-session-end. Session 61 (2026-04-23) removed most `_index.md` catalogs and reframed the rule in positive-space: frontmatter is the source of truth; catalogs exist only where they carry their weight.

## Why

Session 1 found CLAUDE.md at 164 lines with hardcoded counts and inlined reference tables that required maintenance every session. The token economy overhaul reduced it to 62 lines by replacing inlined data with on-demand pointers. This constraint prevents context bloat from recurring.

The cost model is straightforward: every token in a context file is loaded on **every agent invocation**. A 100-token table that could be derived from Glob costs 100 tokens per call, across every call, for the lifetime of the project. Multiply by hundreds of invocations per session and the waste compounds.
