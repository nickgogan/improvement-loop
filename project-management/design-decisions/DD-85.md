# DD-85

> **For agents:** MetaSystem is a single Obsidian vault. Never create nested vaults (`.obsidian/` directories inside system subdirectories). Use HUB.md files for system-scoped navigation. The root HUB.md provides cross-system overview.

## The Constraint

### Single Vault Architecture

MetaSystem is one Obsidian vault with system-scoped views, not multiple vaults composed together.

**Nested vaults are prohibited.** Obsidian's developers strongly discourage nested vaults due to:
- Cross-vault links silently create duplicate files instead of resolving
- Sync (both Obsidian Sync and git-based) breaks unpredictably with multiple `.obsidian/` directories
- No official documentation supports nested vaults

### Navigation Layers

| Layer | Mechanism | Purpose |
|-------|-----------|---------|
| **Cross-system** | Root `HUB.md` | Overview of all systems, recent DDs, active IB items |
| **System-scoped** | Per-system `HUB.md` | Dataview queries scoped to that system's directory |
| **Context switching** | Obsidian Workspaces plugin | Save/restore panel layout, sidebar, open files per system |
| **Filtered views** | Dataview queries on frontmatter | Dynamic tables filtered by `target_system`, `type`, `status`, etc. |
| **Search scoping** | `path:systems/improvement-loop` | Restrict search to one system |
| **Graph filtering** | Graph color groups per system path | Visual system boundaries (already configured) |

### Hub Notes

Each system has a `HUB.md` with Dataview queries scoped to its directory:

| System | Hub Path |
|--------|----------|
| Overview | `HUB.md` (root) |
| Improvement Loop | `systems/improvement-loop/HUB.md` |
| Meta-System | `systems/meta-system/HUB.md` |
| Household OS | `incubator/household-os/HUB.md` |
| Claude Build | `incubator/claude-build/HUB.md` |

Hub notes use Dataview queries against frontmatter properties defined in `_schema.yaml`. They require the Dataview community plugin to render dynamically.

### Obsidian Workspaces (Core Plugin)

Create one workspace per system:
- **Overview** — root-level view, all folders expanded
- **IL** — collapsed to `systems/improvement-loop/`
- **Meta** — collapsed to `systems/meta-system/`
- **HOS** — collapsed to `incubator/household-os/`
- **Build** — collapsed to `incubator/claude-build/`

Workspaces save and restore the full panel state (open files, sidebar, layout). Switch via Cmd+P → "Manage workspaces".

## Why

Perplexity deep research confirmed that every successful large-scale Obsidian implementation uses a single vault with sophisticated filtering, not multiple vaults. Nested vaults create data loss risks (silent file duplication on cross-vault links) and sync failures. The single-vault approach preserves link integrity, works seamlessly with git-based sync, and supports mobile access without vault-switching overhead.
