# DD-46

> **Superseded by DD-103 (2026-06-18).** The `Research → MetaSystem Patterns → Per-System Backlogs` pipeline assumed per-system architect agents pulling from a meta-layer. There are no peer systems and no per-system architect agents. The live pipeline is the engine's own intake → identify → extract → deploy flow (DD-80), terminating in an in-engine promotion to `knowledge/`.

> **For agents:** DD-46 defines how knowledge moves from research into actionable system work. When creating backlog items or planning system work, follow this pipeline.

---

## The Pipeline

```
Research Findings → Improvement Loop → MetaSystem Patterns → Per-System Backlogs
```

---

## Stage 1: Research

- Research Loop processes external sources (videos, articles, tools, frameworks)
- Findings stored in Research Findings DB with source attribution

## Stage 2: Evaluation and Proposal

- Improvement Loop evaluates findings for applicability
- Produces Improvement Proposals with recommendations
- Nick approves or rejects proposals

## Stage 3: Codification

- Approved proposals become codified patterns in MetaSystem
- Patterns are written as reusable guidelines, not system-specific instructions
- Each pattern includes: context, guidance, applicability criteria, examples

## Stage 4: System Consumption

- Per-system agents browse MetaSystem's pattern library
- Agents curate system-specific backlog items by combining:
  - Meta-level patterns (from MetaSystem)
  - Local needs (feature requests, bugs, operational observations)
  - Nick's direct requests
- Backlog items are added to the Implementation Backlog with appropriate Target System

---

## Per-System Agent Topology

Each system has (or will have) architect and product agents:

| System | Architect Agent | Product Agent | Status |
|---|---|---|---|
| **S1: Schema** | Designs schema changes informed by meta patterns | Prioritizes schema backlog | Direction |
| **S2: Operations** | Designs agent configs and workflows | Prioritizes operational backlog | Direction |
| **S3: Build** | Designs build tooling and processes | Prioritizes build backlog | Direction |
| **Improvement Loop** | Designs research and evaluation processes | Prioritizes IL backlog | Direction |

"Direction" = captured as architectural intent, not yet built.

---

## Backlog Composition

A system's backlog is a mix of sources:

| Source | Example |
|---|---|
| **Meta patterns** | MetaSystem recommends error budget pattern → IB item for S2 error handling |
| **Feature requests** | Nick wants a new Notion view → IB item for S1 schema change |
| **Bugs** | Front Desk misrouting items → IB item for S2 fix |
| **Operational observations** | Nick notices ritual fatigue → IB item for S2 ritual redesign |
| **Nick's direct requests** | Anything Nick explicitly asks for |
