# DD-37

> **For agents:** DD-37 contains the foundational design heuristics that govern all systems. Apply these principles before consulting system-specific DDs.

---

## The Five Principles

### 1. Spec Before Build
Design the architecture before writing code or configuring databases. A Build Spec precedes every implementation.

### 2. Complementary Tools, Not Redundant Ones
Every tool serves a unique purpose. No tool should duplicate another's primary function.

### 3. Knowledge Serves Expression
Knowledge is captured not for its own sake but to fuel action. Every capture should have a plausible path to action.

### 4. Start Lean, Refine Later
Deploy the simplest version that works. Add complexity only when the simple version fails.

### 5. Shallow vs. Deep Thinking Distinction
Match tool power to task depth. Shallow processing (triage, routing) vs. deep processing (architecture decisions, creative work).

---

## Application

These principles are applied in order of precedence. If principles conflict (e.g., "spec before build" vs. "start lean"), the resolution is: write a lean spec, then build.
