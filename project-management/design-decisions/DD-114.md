# DD-114

> **For agents:** When you hand-write frontmatter, put prose fields (`summary`, `key_takeaways`, `implementation_notes`, `notes`, `log_entry`, `rationale`, `decision`) under a literal block scalar (`|-`) — never an inline quoted string. Lists get uniform 2-space indent, no duplicates. The canonical rule is in `_schema.yaml`. A git pre-commit hook (`validate_frontmatter.py`) rejects commits with unparseable frontmatter; bypass a single commit only with `git commit --no-verify`.

## Problem

Session 127 fixed **40 frontmatter parse failures** corpus-wide in three classes: (A) unquoted prose scalars containing `: ` parsed as nested mappings; (B) mixed-indent / duplicate simple lists; (C) multi-line unquoted scalars whose continuation held a colon. All three originate **upstream**: every active intake/governance skill hand-writes frontmatter as a text template using *inline quoted* prose scalars (`summary: "..."`), which break when the agent omits the quote, embeds a quote, or soft-wraps the value. The session-127 fix was a one-off downstream patcher (since removed, Rule 11); the producing skills could reintroduce the same defects on the next intake.

## Decision rationale

- **Block scalars are strictly safer than quoting.** Quoting only handles colons, and only if the agent remembers to quote and escape internal quotes. A `|-` block scalar requires zero escaping and absorbs colons, quotes, and multi-line text — covering all three defect classes with one convention.
- **Authoring convention first (Rule 11).** Editing skill templates is sanctioned mechanics, not a new abstraction. It is the cheapest durable fix and the primary layer.
- **The linter earns its keep as a binary check.** Unlike the removed read-guard hook (a heuristic that produced false positives, see `reference_read_guard_hook_removed`), a YAML-parse check is objective: a file either parses or it does not. Its false-positive surface is effectively nil, so the Rule-11 mechanism cost is justified — and Nick explicitly authorized it (option c).
- **No redundant write-path mechanism (option b rejected).** Routing LLM-authored markdown through `kb_parser.write_frontmatter` was a poor fit — no producing skill has a script seam; the agent composes the body inline. The convention + linter cover the inline-authoring path without inventing a shell-out.

## Scope of execution (session 128)

- `_schema.yaml`: added the "Frontmatter authoring rules (YAML safety)" canonical contract.
- Producer skills updated to model block-scalar prose and point to the contract: `research-loop`, `research-query`, `promote-findings`, `watch-blogs`, `/sl`, `/dd`, `/ib`.
- New `operations/kb-maintenance-scripts/validate_frontmatter.py` (validates specific files, `--all` over git-tracked corpus, or stdin paths); reuses `kb_parser.ROOT`.
- Tracked hook `operations/kb-maintenance-scripts/hooks/pre-commit`, installed as `.git/hooks/pre-commit` (symlink). `.git/hooks/` is not version-controlled, so the tracked master + its install line are the reproducible source.
- Verified `kb_parser` is load-bearing (3 importers) and `write_frontmatter` is intentionally retained; no cleanup performed.
