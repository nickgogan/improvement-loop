# DD-91

> **For agents:** Every graduated multi-agent system carries a reflections-to-proposals pipeline. Each agent has an `agents/{name}/reflections/` directory — agent-private, append-only — where it writes self-assessments. The system's Owner runs `/solicit-proposals` to trigger reflection rounds. Agents may also propose ad-hoc without a round. All proposals land in `governance/proposals/`; accepted ones become IB items.

## The Constraint

Every graduated multi-agent system provides a reflections-to-proposals pipeline with six required elements:

1. **Agent-private reflections directory.** Each agent has an `agents/{name}/reflections/` subdirectory owned by that agent. Reflections are append-only (one file per reflection event) and privacy-restricted by convention — only the reflecting agent and the system's Owner read them during solicitation. Cross-agent reads are forbidden. Nick reads all.

2. **Reflection artifact shape.** A reflection records the agent's self-assessment over a defined period: vision/mission/constitution review, effectiveness, efficiency, felt gaps, help needed, free-form commentary. Primarily free-form; a suggested scaffold exists but is not enforced.

3. **Owner-owned solicitation mechanism.** Each system's Owner carries a `/solicit-proposals` skill (or system-local equivalent) that triggers a reflection round. The skill checks reflection freshness, prompts stale agents to re-reflect, collects fresh reflections with optional Owner-provided focus areas, and requests proposals from each agent.

4. **Dual proposal pathways.** Proposals may originate from a solicitation round (structured) OR from an agent's own initiative (ad-hoc, outside a round). Both flow to the system's `governance/proposals/`; both face Nick's review; both convert to IB items on acceptance.

5. **Nick's gate is at review time, not per-step.** Nick reviews accumulated proposals (and, by option, focus-area drafts before a round) — he is not required mid-flow. Rounds run autonomously through reflection and proposal drafting; Nick reviews output.

6. **Invariants preserved.**
   - Reflections are agent-private by convention.
   - Reflections are append-only.
   - Proposals await Nick review before application.
   - The reflection prompt is shared — one prompt serves all agents in a system.
   - Agent-initiated proposals stay lightweight.

### Scope

- **Applies to:** Graduated systems under `systems/` with two or more agents (Owner + at least one sibling counts).
- **First adopter:** Improvement Loop — infrastructure deployed session 51; pipeline live from session 52 onward.
- **Applies at graduation:** Household OS, Claude Build, future graduated systems.
- **Does not apply to:** Single-agent systems (no inter-agent reflection dynamic to codify), incubating systems (shape-unstable — pattern applies at graduation), purely-human systems.

### Implementation obligations per-system

For each in-scope system, adoption requires:

1. `agents/{name}/reflections/` directory for each agent.
2. `/solicit-proposals` skill (or equivalent) in the system's `.claude/skills/`.
3. One shared reflection prompt bundled with the skill.
4. Agent-constitution permissions allowing writes to each agent's `reflections/`.
5. System `CLAUDE.md` cross-link to the reflections pathway.
6. `governance/agent-rules.md` updated to formalize the agent-private reflections boundary.

## Why

Every graduated multi-agent system faces the same gap: producer-on-self self-improvement has no standing channel absent this architecture. Consumer-to-producer feedback (existing) solves a different problem.

Codifying at MetaSystem level delivers:

- **Graduation expectations.** A new graduated system knows it needs the pipeline — no per-system rediscovery.
- **Cross-system learning.** Improvements discovered in one system propagate as MetaSystem-level amendments rather than one-off fixes.
- **Cross-system pattern analysis.** If multiple systems generate reflection-derived proposals about similar concerns, patterns surface that no single system would see alone.
- **Nick-extrication.** This pipeline is the long-term substitute for Nick-as-per-session feedback loop. Agents generate improvement ideas autonomously; Nick reviews accumulated output.
