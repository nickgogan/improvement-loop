# DD-68

> **For agents:** DD-68 defines how the KB is organized taxonomically. Dimensions live in `knowledge/research-dimensions.md`, not in the skill. Read that file at scan start. When a pattern doesn't fit any dimension, flag it as a dimension gap — do not force-fit.

---

## The Constraint

The research knowledge base is organized into **typed dimensions** — named categories that partition the space of agentic coding practices. Each dimension has:
- A name and scope description
- Web search queries (for Perplexity/web scans)
- arXiv queries (for academic papers)

Dimensions are stored in an **externalized registry** at `systems/improvement-loop/operations/references/research-dimensions.md`, separate from the research-loop skill definition. This separation means:
- Queries evolve with each scan without touching the skill
- Dimension additions/removals don't require skill code changes
- The registry is human-readable and editable in Obsidian

## Adding a New Dimension

A new dimension is warranted when:
- Multiple findings (5+) exist that don't cleanly fit any existing dimension
- The proposed dimension covers a distinct concern, not just an overlap zone between existing dimensions
- Evidence exists across multiple sources (not just one authority's framing)

After adding a dimension:
1. Update `research-dimensions.md` with name, scope, and queries
2. Run `/dimension-rebalance` to reclassify existing findings
3. Update the research-loop skill's dimension count and category enum

## Dimension Gap Detection

During extraction, if a pattern doesn't fit any dimension, flag it under "Dimension Gaps" in the delta report. Do not force-fit patterns into dimensions — gaps are signal for future dimension additions.
