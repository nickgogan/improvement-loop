# DD-87

> **For agents:** The IL research dimensions registry now has 11 dimensions. Dimension 11 is "Agentic OS" — patterns for using AI agents as a personal/business operating system. This is distinct from Context Engineering (Dim 1), which covers what agents see at runtime. Agentic OS covers how humans use agents as their primary operating system for work and life. Findings in this dimension use the category "Agentic OS".

## The Constraint

The research dimensions registry (`operations/references/research-dimensions.md`) gains an 11th dimension:

| Dimension | Focus |
|-----------|-------|
| **Agentic OS** | How humans use AI agents as their primary operating system for personal productivity, knowledge management, and business operations |

### What It Covers

- Personal knowledge management with AI agents (second brain, vault-as-OS)
- Obsidian + AI agent integration patterns (CLI, terminal plugins, graph views)
- Scheduled agent tasks for life/business operations (morning briefs, meeting transcript ingestion, analytics rollups)
- File-based personal OS architecture (folder structure, index files, CLAUDE.md as routing layer)
- Context infrastructure maturity models (chat → projects → skills → file access → second brain → business OS)
- Team context sharing and permission patterns (sync, relay plugins, access control)
- Experiment/ritual tracking with agent assistance
- Daily routine automation and habit-tracking workflows

### Why It's Distinct

- **Context Engineering** (Dim 1) = the infrastructure — what agents see at runtime, how context is injected
- **Agentic OS** (Dim 11) = the application layer — the workflows, rituals, and patterns that let agents manage your knowledge, schedule, experiments, and operations

### Finding Category

New findings in this dimension use `category: "Agentic OS"` in frontmatter.

## Rationale

The IL has been encountering a growing cluster of sources about personal/business OS patterns (Obsidian+Claude Code, second brain architectures, scheduled life-management tasks) that don't fit cleanly into existing dimensions. Context Engineering is about agent infrastructure; these patterns are about human-agent operational workflows. Creating a dedicated dimension ensures these patterns are tracked systematically rather than force-fit into Context Engineering.
