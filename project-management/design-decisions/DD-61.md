# DD-61


> **Superseded by [[DD-119]] (2026-07-12). The milestone-gate invariant survives in DD-119 §3 as the milestone-boundary application of DD-29; the agent-team development-loop framing here predates the four-agent model.**
> **For agents:** DD-61 defines the development loop that agent teams follow. Work is organized around milestones. Within a milestone, agents collaborate freely. At milestone completion, a mandatory human gate controls advancement. No agent may advance a milestone without human sign-off.

---

## Core Decision

The agent team operates in a loop organized around milestones. This is the core operational pattern for all incubator projects.

### Loop Structure

```
MILESTONE N
│
├── Strategy Phase
│   ├── PO reviews/refines acceptance criteria for this milestone
│   ├── Architect confirms architectural approach for this milestone's scope
│   └── TPM produces task list with exit criterion
│
├── Execution Phase
│   ├── Engineers implement tasks
│   ├── Each task: implement → self-test → next task
│   └── Blockers escalate: Engineer → TPM → Architect → PO as needed
│
├── Verification Phase
│   ├── Tester validates all tasks (different POV from implementing engineers)
│   ├── Architect reviews for architectural compliance
│   ├── PO verifies acceptance criteria are met
│   └── Exit criterion evaluated: pass → Human Gate | fail → back to Execution
│
└── HUMAN GATE (mandatory)
    ├── Human performs end-to-end testing and edge case testing
    ├── Human provides feedback: accept / revise / reject
    ├── Accept → proceed to Milestone N+1 Strategy Phase
    └── Revise/Reject → structured feedback injected into next Strategy Phase
```

### Intra-Milestone Autonomy

Within a milestone, agents hand off freely between each other without human intervention. This enables:

- Backend engineer completes work → frontend engineer picks up dependent tasks
- Engineer self-tests → tester validates independently
- TPM reorganizes remaining tasks based on blockers

The human is NOT in the loop during execution and verification. Agents self-organize around the task list.

### Testing Hierarchy

| Level | Who | What | When |
|-------|-----|------|------|
| Self-test | Implementing engineer | Unit tests, integration tests for own work | After each task |
| Peer-test | Tester agent | Cross-cutting validation, regression, adversarial testing | Verification phase |
| Compliance check | Architect | Architectural adherence, pattern consistency | Verification phase |
| Acceptance check | PO | User-facing criteria met | Verification phase |
| E2E + edge cases | **Human** | End-to-end flows, edge cases, gut-check | Human Gate |

### Exit Criterion

Each milestone MUST have an explicit, testable exit criterion defined by the TPM (in collaboration with PO) before the Execution phase begins. The Verification phase uses this criterion — not a vague sense of "done" — to determine pass or fail.

### The Human Gate Is Not Optional

No milestone advances without human sign-off. This is a hard constraint, not a default. It generalizes DD-29 (IL human gates) to all agent team work.
