# DD-80

> **For agents:** Do not use `/research-proposer` or write to `improvement-proposals/`. Use `/identify-artifacts` to classify findings into forms, then `/extract-artifacts` to draft and write staged artifacts from the approved report. The pipeline is: Finding -> /identify-artifacts -> Report -> [Nick reviews] -> /extract-artifacts -> extracts/ -> [deploy].

---

## The Decision

The three-stage pipeline (Research -> Propose -> Codify) is simplified to two stages (Research -> Extract). The Proposer stage and its intermediate proposal documents are eliminated.

**What changes:**

1. Two skills replace the Proposer (IB-147): `/identify-artifacts` classifies findings into forms using the Form Router rubric and produces an identification report; `/extract-artifacts` reads an approved report and drafts staged artifacts in `systems/improvement-loop/extracts/`.
2. The filtering function previously owned by the Proposer (priority gating, evidence-strength assessment) is absorbed into `/identify-artifacts` as a scoping step. Classification is Sonnet-parallelizable; drafting runs on the smaller approved set.
3. `improvement-proposals/` is archived. Existing 6 proposals are preserved as historical artifacts; no new proposals will be produced.
4. `/research-proposer` skill is deprecated. Not deleted — retained for reference but no longer invoked.

**What does NOT change:**

- **Human gate (DD-29):** Preserved. `/extract-artifacts` presents candidates for user approval before writing.
- **KB ownership (DD-41):** Research findings, sources, and authorities remain IL-owned operational data.
- **Pull model (DD-46):** Systems still pull from `meta-system/knowledge/` on the read side. Deployment from `extracts/` to enforcement locations is a separate act.
- **Form classification rubric:** The rubric in `systems/improvement-loop/operations/references/form-classification-rubric.md` remains the decision spec for classification. DD-75 through DD-79 still apply.

**Simplified pipeline:**

```
Research KB (IL)  ->  /identify-artifacts  ->  Report  ->  [Nick reviews]  ->  /extract-artifacts  ->  extracts/ (IL)  ->  [human deploy]
  findings/           classify (Sonnet)      loop-reports/   approve/reject    draft + write          rules/ templates/ etc.        Nick deploys
```

## Why

Session 22's 50-finding calibration revealed that 92% of findings are patterns. The Proposer's primary output — a recommendation document — added no value beyond what the finding itself already contains (priority, evidence strength, applicability). The proposal document was an intermediate artifact nobody consulted after approval.

The key insight: filtering and classification are lightweight (Sonnet-parallelizable), while drafting benefits from a smarter model on a smaller approved set. Splitting identification from extraction avoids wasted drafting on rejected classifications and gives Nick a better review surface — a classification report is easier to review than a pile of draft artifacts. The human gate between identification and extraction provides the same approval guarantee that the proposal gate provided, with less ceremony.

Staging in `extracts/` within the IL provides the blast-radius safety that DD-39 (codify-before-apply) was designed for — artifacts don't reach enforcement locations until explicitly deployed.
