# DD-47

> **For agents:** DD-47 defines the workspace filesystem layout. When navigating MetaSystem, use this DD to understand where things live and why. The PARA mapping tells you the organizational principle behind each top-level directory.

---

## Core Decision

The MetaSystem workspace root is organized with these top-level entries:

| Directory | PARA Role | Purpose |
|---|---|---|
| `implementation-backlog/` | Governance Infrastructure | Active build queue and execution tracking (promoted per DD-42) |
| `system-log/` | Governance Infrastructure | Audit trail across all systems (promoted per DD-42) |
| ~~`meta-system/`~~ | ~~Resources~~ | [Updated 2026-04-05: moved into `systems/meta-system/` — now a systems/ peer] |
| `systems/` | Areas | Graduated permanent infrastructure (Household OS, Claude Build, Meta-System, Improvement Loop) |
| ~~`improvement-loop/`~~ | ~~Areas~~ | [Updated 2026-04-05: moved into `systems/improvement-loop/` — now a systems/ peer] |
| `incubator/` | Projects | New projects, experiments, prototypes with end dates |
| ~~`s1-schema/`~~ | ~~Reference~~ | [Updated 2026-04-05: s1-schema content moved to `incubator/household-os/knowledge/reference/` and `incubator/household-os/archive/s1-extraction/` per DD-58] |
| `archive/` | Archives | Workspace-level historical artifacts |

**Note:** Design Decisions were originally promoted to root level per DD-42, then further distributed to system-scoped `project-management/design-decisions/` folders per DD-55.

## PARA Mapping

| PARA Category | Directories | What Lives Here |
|---|---|---|
| **Projects** | `incubator/` | Active experiments, new work with end dates |
| **Areas** | `systems/` (includes Household OS, Claude Build, Meta-System, Improvement Loop) | Ongoing infrastructure with standards to maintain |
| ~~**Resources**~~ | ~~`meta-system/`~~ | [Updated 2026-04-05: meta-system moved into systems/ — PARA Resources now lives at `systems/meta-system/`] |
| **Archives** | `archive/` (+ scoped archives within systems) | Historical, completed, retired work |

---

## Governance Database Promotion

Per DD-42, cross-system operational databases with high write frequency are promoted to root-level peers. The following databases move from `s1-schema/databases/` to workspace root:

| Database | Source | Current Destination |
|---|---|---|
| Design Decisions | `s1-schema/databases/design-decisions/` | System-scoped `project-management/design-decisions/` folders (DD-55) |
| Implementation Backlog | `s1-schema/databases/implementation-backlog/` | `implementation-backlog/` (root) |
| System Log | `s1-schema/databases/system-log/` | `system-log/` (root) |

Research databases (findings, sources, authorities, proposals) are IL-owned reference data, now in `systems/improvement-loop/`.

Design Decisions were initially promoted to root level, then further distributed to enforce boundary isolation between systems (DD-55).

---

## Shared Governance Content

The former `shared/` directory (values.md, principles.md, vocabulary.md) moves to `systems/meta-system/governance/`. The constitution is copied from s1-schema to `systems/meta-system/governance/constitution.md`. These are the local-first authoritative sources for governance documents.

---

## Context Flow

```
Layer 1: ALWAYS LOADED (root CLAUDE.md)
  -> Constitution: values, principles, vocabulary, pipeline
  -> PARA mapping, cross-system rules

Layer 2: DIRECTORY-ACTIVATED (system/project CLAUDE.md)
  -> incubator/claude-build/CLAUDE.md when working in Claude Build
  -> incubator/{project}/CLAUDE.md when working on a project
  -> systems/meta-system/CLAUDE.md when working on patterns/templates

Layer 3: ON-DEMAND (skills invoked by user or agent)
  -> .claude/skills/bootstrap/ from anywhere
  -> incubator/claude-build/.claude/skills/* when in Claude Build

Layer 4: REFERENCED (@-imports pulled as needed)
  -> */project-management/design-decisions/* for DD data (system-scoped per DD-55)
  -> implementation-backlog/* for IB data
  -> systems/meta-system/patterns/* for cross-system patterns
  -> incubator/household-os/knowledge/reference/* for architecture docs
```
