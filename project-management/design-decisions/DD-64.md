# DD-64

> **For agents:** DD-64 defines what happens when `/bootstrap` creates a new incubator project. Beyond the existing folder scaffolding, bootstrap now also instantiates an agent team from templates and sets up the initial artifact structure for the development loop.

---

## Core Decision

When the bootstrap skill instantiates a new incubator project, it creates not just the fractal folder structure (DD-52) but also a project-scoped agent team and initial artifact placeholders.

### Bootstrap Agent Instantiation Steps

1. **Copy agent templates** from `systems/meta-system/knowledge/templates/agent-templates/` into the project's `.claude/agents/` directory
2. **Populate project context** in each agent definition — project name, tech stack (if known), current phase
3. **Create initial artifact structure:**
   - `docs/prd.md` — PRD placeholder (PO's first artifact)
   - `docs/architecture.md` — Architecture doc placeholder (Architect's first artifact)
   - `docs/tasks.md` — Task list placeholder (TPM's first artifact)
4. **Set the first milestone** as "Project Definition" — exit criterion: approved PRD and Architecture doc
5. **Brief the PO agent** on the human's initial idea from the brainstorming session

### Team Composition Selection

Bootstrap should ask the human which team composition to use:

| Template | Roles Included | When to Use |
|----------|---------------|-------------|
| **minimal** | PO + Engineer | Small utility projects, scripts, tools |
| **standard** | PO + Architect + TPM + Engineer + Tester | Most software projects |
| **extended** | Standard + domain specialists (backend, frontend, middleware) | Full-stack applications |

The human selects during bootstrap. The default is **standard**.

### What Bootstrap Is NOT

- Bootstrap is NOT a member of the agent team
- Bootstrap does NOT make product or technical decisions
- Bootstrap does NOT persist after project creation — it runs once and exits
- Bootstrap is the meta-system mechanism that creates the team (DD-49)

### Template vs Instance

- **Templates** (`systems/meta-system/knowledge/templates/agent-templates/`) are canonical role definitions maintained at the meta-system level. They contain the role's cognitive disposition, access model, and default configuration.
- **Instances** (project's `.claude/agents/`) are copies customized with project-specific context. Once created, the instance is owned by the project — meta-system template updates do not propagate automatically.
