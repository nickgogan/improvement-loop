# DD-82

> **For agents:** The IL has four agents. Owner is the default persona and system steward (DD-86). Researcher writes to findings/sources/authorities. Codifier writes to extracts/ and operations/. Librarian writes nothing — read-only. Handoffs are file-mediated via `pipeline_status` field, not direct communication. Nick triggers every stage transition.

## The Constraint

The Improvement Loop operates as a 4-agent system:

| Agent | Role | Skills | Write Scope |
|-------|------|--------|-------------|
| **Owner** | System steward — default persona (DD-86) | 6 (system-health, process-feedback, maintain-docs, system-audit, translate-governance, solicit-proposals) | governance/, governance/proposals/ (curation only), project-management/design-notes/, operations/system-log/, agents/owner/reflections/, docs |
| **Researcher** | Stage 1: Intake & KB maintenance | 12 (research-query, research-loop, source-triage, watch-upstream, watch-blogs, transcript-fetcher, perplexity-research, repo-analyzer, promote-findings, linkage-repair, finding-crosslink, dimension-rebalance) | research-findings/, research-sources/, research-authorities/, watched-libraries/, watched-blogs/, agents/researcher/reflections/, operations/ |
| **Codifier** | Stages 2-3: Classification, extraction, synthesis | 4 (identify-artifacts, extract-artifacts, synthesize-guide, reassess-priorities) | extracts/, project-management/design-notes/, agents/codifier/reflections/, operations/ (+ pipeline_status metadata on findings) |
| **Librarian** | Consumption layer: KB queries & design guidance | 3 assess-* skills (assess-agent, assess-prompt, assess-skill) | agents/librarian/reflections/; operations/system-log/ for boundary-case encounter logs via the assess-* skills (see boundary-case tracking design note) — otherwise read-only |

**Handoff protocol:**
- Agents never communicate directly
- Handoffs are mediated by the filesystem: `pipeline_status` field on findings is the interface contract
- `pipeline_status` transitions: `raw` (set by Researcher) → `synthesized` or `extracted` (set by Codifier)
- Nick triggers every stage transition — no agent autonomously invokes another agent's skills
- Each agent additionally owns a private `agents/{name}/reflections/` subdirectory for self-reflections consumed by `/solicit-proposals` rounds (see DD-91)

**Agent definitions:** `systems/improvement-loop/agents/{name}/agent.md`
**Handoff protocol:** `systems/improvement-loop/agents/handoff-protocol.md`
**Librarian engine definition:** `.claude/agents/librarian.md` (invocable from anywhere)

## Why

DD-30 defined a two-agent model (Researcher + Proposer). DD-80 eliminated the Proposer stage. This session designed the replacement architecture: a 3-agent model with explicit ownership boundaries, skill inventories, and handoff contracts. The agents were designed using the IL's own guide KB (G1, G3, G9, G10), dog-fooding the knowledge the pipeline produced.

The Librarian is a new addition — a consumption-layer agent that reads the KB to answer questions and provide design guidance. It exists because the KB is now large enough (440 findings, 11 guides, 24 staged artifacts) to need a dedicated interface.
