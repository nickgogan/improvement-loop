# DD-53

> **For agents:** DD-53 establishes that work within systems goes through defined agents, not ad-hoc Claude Code. When building or operating a system, use the agents defined in that system's agents/ directory. If no suitable agent exists, create one rather than working directly.

---

## Core Decision

The agents/ directory in each unit is the primary interface for all work. Each agent is a "team member" with:

- **skills/** — capabilities the agent can execute
- **workflows/** — multi-step sequences
- **hooks/** — triggers and automations

This principle ensures:
1. **Auditable work** — agents provide identity and scope boundaries
2. **Predictable behavior** — agents have defined capabilities, not open-ended access
3. **Reusable patterns** — agent definitions can be templated and shared across systems
4. **Human oversight** — agent scope boundaries make review gates meaningful

---

## Relationship to .claude/agents/

- `.claude/agents/` holds engine-facing definitions consumed by Claude Code's harness (subagent files)
- `agents/` holds the richer team-member context (skills, workflows, hooks per agent)
- The engine definition is a subset of the full agent description
- Both coexist within the same unit

---

## When Raw Claude Code Is Acceptable

- Initial exploration and research (reading, searching)
- One-off queries that don't modify system state
- Creating new agent definitions (bootstrapping the agentic layer itself)
- Emergency fixes when agent infrastructure is broken
