Bundles the schema field addition with its retroactive backfill in IB-155 precedent style (schema change atomic with the backfill it requires). **Scope.** Two work items, both required for DD-100's structural contract to be operative on the next template/agent extract write. **Item 1 — `_schema.yaml` `version: integer` field.** Add `version` integer field to the frontmatter contract for `template` and `agent` extract types in `_schema.yaml`. Field requirement per DD-100 §The Constraint: optional on v1 (legacy artifacts predate DD-100; absence treated as `version: 1`); required on v2+. Field semantics: matches the suffix in the filename — `<name>-v2.md` carries `version: 2`; `<name>-v3.md` carries `version: 3`; the unsuffixed `<name>.md` either omits the field (legacy) or carries `version: 1` (explicit post-backfill). Placement: the existing `# === Lifecycle Tracking (non-guide extracts only — DD-95) ===` block (line 43 of `_schema.yaml`) is too wide — it covers rules + skills + templates + agents. The `version` field is template/agent ONLY (rules/skills use DD-97's extension rubric per DD-100 §Scope and Non-Goals). Recommended placement: new sibling block `# === Versioning (template/agent extracts only — DD-100) ===` immediately after the DD-95 Lifecycle Tracking block, with explanatory comments stating the optional-on-v1 / required-on-v2+ rule, the integer-only constraint (no semver, no decimals, no minor versions per DD-100 §The Constraint), and the filename-suffix correspondence. Executor may instead annotate the field inside the existing block with conditional comments — both are spec-compliant; new block is cleaner for separation of DD-95 vs DD-100 concerns. Other extract types (rule, skill) and other frontmatter classes (guide, finding, source, authority) are unaffected by this schema change. **Item 2 — Retroactive `version: 1` backfill.** Verified counts at filing time (session 75 — supersedes DD-100's '~12 templates and ~5 agents' estimate): **6 templates** in `extracts/templates/` (excluding `_index.md`) + **3 agents** in `extracts/agents/` (excluding `_index.md`). Backfill writes `version: 1` to each artifact's frontmatter — placement adjacent to other lifecycle fields (after `extraction_date` or after the DD-95 `last_change_*` pair). Frontmatter-edit only: NO new files created during backfill; NO `<name>-v2.md` retroactively created for any artifact (versioning starts forward from DD-100's landing per DD-100 §Backfill). Backfill is optional per DD-100 §Backfill ('absence treated as `version: 1`') but explicit makes the contract self-describing — the IB executes the backfill to remove the implicit-vs-explicit ambiguity for legacy artifacts. **Rules (subset of DD-100 §Rules for `/extract-artifacts`).** (1) Schema field is integer-only — no decimals, no semver, no minor versions. (2) Field is optional on v1 (legacy compatibility); required on v2+. (3) Backfill is frontmatter-edit only; never creates new versioned files. (4) The `version: 1` value matches the implicit semantics of the unsuffixed filename — adding it makes DD-100's contract explicit, does NOT promote to or imply a v2 lineage. **Acceptance Criteria (subset of DD-100 §Acceptance Criteria).** (i) `_schema.yaml` documents the `version` field for template and agent extract types; required on v2+, optional on v1; other extract types unchanged; (ii) All 6 templates in `extracts/templates/` carry `version: 1` in frontmatter post-backfill; (iii) All 3 agents in `extracts/agents/` carry `version: 1` in frontmatter post-backfill; (iv) No new `<name>-v2.md` files are created by the backfill; (v) The schema field's documentation comments explicitly state: integer only, optional v1, required v2+, filename-suffix correspondence, scope (template/agent only). **Dependencies.** DD-95's Lifecycle Tracking block in `_schema.yaml` (already present per session 70 SL §Schema Update — the precedent for adding lifecycle frontmatter blocks). Blocks IB-162: the `/extract-artifacts` template version-bump path requires this schema field to exist before it can write `version: N+1` to v2+ artifacts. **Touch Points.** `_schema.yaml` (single new comment block + field; placement after line 51 of current schema); `extracts/templates/*.md` (6 files — frontmatter `version: 1` add); `extracts/agents/*.md` (3 files — frontmatter `version: 1` add). Total: 1 + 6 + 3 = 10 files modified. **Form precedent.** IB-155 Item 2 (retroactive backfill bundled with the structural change that requires it — 11 changelog stubs alongside the appender skill change); session 70 SL §Schema Update (DD-95 fields added to `_schema.yaml` in a new lifecycle block — the structural pattern this IB extends with a sibling block)."
