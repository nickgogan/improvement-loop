# IB-169: Consolidate the two audit-report homes

Two skills write audit output to two different locations:

| Skill | Writes to | Shape |
|-------|-----------|-------|
| `/audit-system` (top-altitude composition) | `audit-reports/` (top level) | dated run dirs: `manifest.md`, `findings.md`, `summary.md` + `runs.md` index |
| `/system-audit` (Owner consistency check) | `operations/audit-reports/` | single dated report file |

Both are documented in CLAUDE.md, so nothing is broken — but two homes for "audit reports" reads
as accidental rather than intentional.

## Why P3 / discuss-first

Cosmetic/structural, not load-bearing. Flagged by Nick (2026-06-19) to **talk through in a future
session** rather than resolve mechanically. Moving `/audit-system`'s output path touches the skill
definition and anything that consumes `audit-reports/runs.md`, so it warrants a deliberate decision,
not a sweep edit.

## Options

- **(a) Leave documented-as-distinct** — current state; zero churn.
- **(b) Consolidate under `operations/audit-reports/`** with a per-skill subfolder — one "audit
  reports" home; requires editing `/audit-system`'s output path + `runs.md` pointer.
- **(c) Consolidate under top-level `audit-reports/`** — move `/system-audit` output up instead.

## Trigger

Next session that touches audit tooling, or when Nick wants to settle it.

## Resolution — session 123 (2026-06-19) → DD-110

**Done.** Verified the two reports are genuinely distinct (per-artifact contract conformance vs.
system drift/consistency), so the fix was **disambiguation, not consolidation** (options b/c
rejected — they'd re-mix two report shapes). Resolved via **DD-110**:
- `/audit-system` renamed **`/audit-artifacts`**; `/system-audit` kept (breaks the anagram with one rename).
- Both homes moved under `operations/`: `operations/artifact-audits/` (`/audit-artifacts`) and
  `operations/system-audits/` (`/system-audit`). Root `audit-reports/` removed.
- `/audit-artifacts` output contract changed to always write under `<target>/operations/`.
