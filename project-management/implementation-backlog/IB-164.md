notes: "Phase-3 lifecycle bundle (alongside IB-159, IB-160, IB-161, IB-162, IB-163). Implements DD-101's reader/writer side — `/extract-artifacts` accepts harvest queue rows as input on Nick-scoped invocation, promotes approved rows through the standard extraction machinery (DD-97 for rule/skill, DD-100/IB-162 for template), and updates the queue row's status to capture the resolution. **Scope.** Three work items, all required for DD-101's promotion path to be operative once IB-163's queue files start accumulating Nick-approved rows. **Item 1 — Queue-row input mode.** Add a new invocation mode to `/extract-artifacts` that accepts a queue row as input (Nick's deliberate scoping, not automatic queue polling per DD-101 §Rules for `/extract-artifacts` item 1). Suggest argument shape `--harvest-row <guide-stem>::<target-form>::<headline-slug>` or `--harvest-queue <path-to-queue-file> --row-id <slug>` — executor's choice; the spec requires only that invocation be explicit, not the exact arg name. The skill `/extract-artifacts` does NOT automatically poll harvest queues — it never reads queue files unless explicitly invoked with a row reference. On invocation: read the named queue row from `extracts/guides/<guide-stem>.harvest-queue.md`; verify the row's status is `nick-approved` (NOT `queued`, NOT `nick-dismissed`, NOT `extracted`, NOT `superseded`) — abort with structured error if status is anything other than `nick-approved`. The queue row's source_finding pointer becomes the `source_finding` for the new artifact; the row's target form becomes the `assigned_form`; the row's source excerpt + Codifier's reading + suggested headline feed the draft. The original pattern finding remains pattern-classified throughout per DD-101 §Promotion to `/extract-artifacts`; its `consumed_by[]` array gains the new harvested artifact's pointer alongside the original guide's. DD-77's 'Router picks one form, full stop' is preserved — the Router never assigned a secondary form; the harvest is an extract-time consumer-side resolution. **Item 2 — Downstream DD chaining.** When the queue row's target form is `rule` or `skill`, **DD-97's extension rubric fires** — `/extract-artifacts` performs its existing Step 1.7 corpus scan (per IB-158) over `extracts/rules/` or `extracts/skills/` and may emit an extension proposal instead of creating a new artifact. The extension proposal is a separate artifact from this DD's queue; the queue row's eventual resolution captures the outcome (`extracted to [[<new-artifact-stem>]]` for new-artifact path; `merged into [[<existing-artifact-stem>]]` for extension-applied path). When the queue row's target form is `template`, **DD-100's version-bump rubric fires (per IB-162)** — `/extract-artifacts` performs the template corpus scan and may identify the harvested candidate as an evolution of an existing template, triggering version bump rather than new template creation. The queue row's resolution captures the outcome (`extracted to [[<new-template-stem>]]` for new template; `version-bumped to [[<template-v_N+1-stem>]]` for version bump path). Agent target form is impossible per IB-163's queue write-side suppression — but defensive: if a queue row carries `target form: agent`, abort with structured error (DD-82 invariant + DD-101 §Rules for `/synthesize-guide` item 3 should have prevented this; defensive abort catches a contract violation upstream). **Item 3 — Queue row status update on extraction / dismissal / merge.** The promotion path writes back to the queue file to update the row's Status and Resolution fields per DD-101 §Rules for `/extract-artifacts` items 3–5: (a) On successful extraction (whether new artifact, DD-97 extension, or DD-100 version bump), the originating queue row's Status is updated to `extracted` with Resolution = `extracted to [[<artifact-stem>]]` (or `merged into [[<existing-stem>]]` if DD-97 extension applied; or `version-bumped to [[<template-v_N+1-stem>]]` if DD-100 version bump applied). The summary table at the top of the queue file is updated in lockstep with the per-row details. (b) On Nick's `dismiss as inline` ruling against a queued row (a separate Nick action that may precede or replace `/extract-artifacts` invocation): Status updated to `nick-dismissed`; Resolution = `dismissed`; the row is RETAINED in the queue for audit; no artifact is created. The skill mode that performs this update is invoked separately (suggest `--harvest-dismiss <row-id>` flag — executor's choice) and writes nothing else; this is a queue-only operation. (c) On Nick's `merge into existing [[<artifact-stem>]]` ruling: Status updated first to `nick-approved` (Nick's gate decision) then to `extracted` after `/extract-artifacts` runs the merge (which is structurally an extension under DD-97). Resolution captures the merge target. **Item 4 — Procedure-table + DD-table updates.** Failure-modes table gains rows for: (i) auto-extraction from queue row with status `queued` (procedural violation — DD-101 §Rules for `/synthesize-guide` item 7 + this IB's Status check); (ii) queue-row reference resolves to a non-existent row (typo or stale row-id); (iii) queue-row target form is `agent` (defensive — should be impossible per IB-163; abort if encountered); (iv) queue-row Status is anything other than `nick-approved` on extraction invocation (abort); (v) queue-write-back failure mid-extraction (the artifact got written but the row status update failed — left in `nick-approved` state with the artifact existing in `extracts/`; recovery is human-mediated re-run of the status update). Design Decisions table gains DD-101. **Rules (subset of DD-101 §Rules for `/extract-artifacts`).** (1) Read queue rows on explicit invocation only; never auto-poll harvest queues. (2) DD-97 fires for rule/skill targets; DD-100/IB-162 fires for template targets; agent targets are impossible by construction (defensive abort). (3) Update queue row on extraction; capture resolution per the closed Resolution enum. (4) Update queue row on dismissal (Nick rules `dismiss as inline`); status `nick-dismissed`; row retained. (5) Update queue row on merge (Nick rules `merge into existing`); status `nick-approved` → `extracted` after merge runs. (6) Original pattern finding remains pattern-classified; `consumed_by[]` gains the new artifact's pointer. (7) Status check on invocation: `nick-approved` only; abort on any other status. **Acceptance Criteria (subset of DD-101 §Acceptance Criteria).** (i) Nick rules `nick-approved` on a queued row; `/extract-artifacts` invoked with the row — new rule artifact written (or existing extended per DD-97); queue row status updated to `extracted` with pointer to the resulting artifact; (ii) Nick rules `dismiss as inline` on a queued row; queue-only update mode invoked — row status updated to `nick-dismissed`; row retained in queue; no artifact created; (iii) Codifier extracts from a queue row with status `queued` (no Nick ruling) — procedural violation, abort with structured error, flagged in next governance audit; (iv) Queue row's target form is `rule` and the candidate is semantically similar to an existing rule — DD-97's extension proposal fires when `/extract-artifacts` runs on the row; row resolution captures `merge into existing [[<existing-rule-stem>]]`; (v) Queue row's target form is `template` and the candidate is an evolution of an existing template — DD-100's (IB-162) version-bump path fires when `/extract-artifacts` runs on the row; row resolution captures `version-bumped to [[<template-v_N+1-stem>]]`; (vi) Queue row's target form is `agent` (defensive — should be impossible per IB-163) — abort with structured error citing DD-82 + DD-101 §Rules for `/synthesize-guide` item 3 invariant violation upstream. **Dependencies.** **Blocked by IB-163** — queue files with `nick-approved` rows are the input shape this IB consumes; without IB-163's queue-write-side, there is no input.
