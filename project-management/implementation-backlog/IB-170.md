# IB-170: Rationalize concept docs, agent reference/helper files, and the knowledge/ folder

A structural-organization question Nick flagged on 2026-06-19. Not a mechanical cleanup — a deliberate placement-and-ownership decision to be specced before any files move.

## The immediate symptom

During the DD-110 post-collapse framing reconciliation (session 123), concept docs were found split across two homes:

- Per-artifact concept docs — `skill.md`, `agent.md`, `prompt.md`, `memory.md` — live in `operations/references/librarian/`.
- The harness concept doc — `harness.md` — lives in `knowledge/reference/`.

Same class of artifact (Librarian concept docs / configuration axes), two different homes.

## The broader question

How should these three things be organized and how do they relate?

1. **Concept docs** — the Librarian's middle-altitude configuration axes (skill / agent / prompt / harness / memory), each with §Composition + §Construction.
2. **Agent / persona reference + helper files** — material under `agents/` that supports the Owner / Researcher / Codifier / Librarian dispositions.
3. **The `knowledge/` folder** — `patterns/`, `guides/`, `templates/`, `reference/`, `schematics/`.

Open sub-questions: Is `operations/references/` the right home for concept docs, or should they live in `knowledge/reference/`? What distinguishes "operational reference" from "knowledge reference"? Where do agent-specific helper files sit vs. shared knowledge? Does the three-altitude model (DD-104) suggest a cleaner placement taxonomy?

## How to approach

- **Discuss-first.** Content/architecture decision; Nick gates the taxonomy.
- **Spec before build** (Charter value). Produce a placement/ownership spec; only then move files (with `git mv`, updating all pointers).
- Rule 11: don't manufacture a taxonomy for symmetry — let the concrete inconsistencies (e.g., the concept-doc split) drive the minimum viable reorganization.

Flagged by Nick (2026-06-19) at session 123 close, building on the concept-doc-split observation surfaced while reconciling DD-110's post-collapse framing follow-up.
