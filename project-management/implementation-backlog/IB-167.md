# IB-167: Instantiate MetaSystem Owner agent

Establish the system-steward agent for Meta-System per the DD-86 pattern. Improvement Loop has an Owner; Meta-System is also a graduated system but currently lacks one.

## Why P1

This is a precondition for the MetaSystem capability roadmap (session 106, step F). Building `/audit-system`, `/design-harness`, and other system-level operations without a steward means the new capabilities accumulate drift, governance gaps, and unprocessed feedback — exactly the conditions DD-86 was created to prevent.

## Relationship to Other IB Items

- **Distinct from IB-142** — IB-142 scopes the vault-curator and knowledge-indexer agents (frontmatter validation, cross-reference integrity, pattern indexing). The Owner is a different role: system steward, governance translator, conversational front door. Sequencing: Owner first (this item), then validators/indexers (IB-142).
- **Enables session 106 cross-system roadmap step F** — MetaSystem structural setup and capability roadmap depend on an Owner being instantiated.

## Scope Notes

- Follow the IL Owner agent.md constitution shape — the structural pattern is established.
- Skill reuse decision pending: does the MetaSystem Owner inherit IL Owner skills (governance translation, health, feedback, maintain-docs, audit, reflections) or get MetaSystem-specific equivalents? Lean toward shared skills with system-scoped configuration; revisit if scope drift surfaces during build.
- Engine subagent: create `.claude/agents/meta-system-owner.md` peer to `.claude/agents/owner.md` so the agent is invocable from anywhere in the workspace.
