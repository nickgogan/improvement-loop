## What It Is

A context loading architecture where every file and directory is pre-processed into three representation tiers: L0 (abstract, ~100 tokens — generated by a semantic prompt at ingest), L1 (overview, ~2k tokens — structural summary), and L2 (full content, unlimited). The retrieval system traverses tiers progressively: vector search scores candidates at L0, reranking descends into promising directories at L1, and full content is loaded at L2 only for top-ranked results. Token budget is enforced at each tier boundary.

## Why It Matters

The existing KB has findings on tiered context injection and three-layer chain-loading, but those operate at the file granularity (which files to load). L0/L1/L2 operates at the content granularity (how much of each file to load). This addresses the fundamental problem: loading full content for all potentially relevant files is wasteful, but loading nothing until selected means the selection can't use content signals. The three-tier approach gives the retrieval system content-aware scoring without full-content cost.

## Why People Are Using It

Observed in [OpenViking](https://github.com/volcengine/OpenViking) — see [[openviking-analysis]] for structural details. OpenViking generates L0/L1 representations at ingest time and stores them alongside the original content. The retrieval pipeline uses L0 for initial candidate filtering, L1 for directory-level reranking, and L2 for final content delivery. MetaSystem's CLAUDE.md chain-loading is a partial implementation of this concept (index files function as L0/L1).

## Potential Alternatives

- Binary load/skip (current MetaSystem approach — either load a file or don't)
- Chunked retrieval with overlap (traditional RAG)
- Summary-then-expand (single expansion step, not three tiers)

## Potential Improvements

Could be applied to MetaSystem's `_index.md` files — they already function as L0/L1 but without the formal tier labels or automated generation.

## Potential Failure Modes

- L0/L1 generation quality depends on the summarization model
- Pre-processing cost at ingest time
- Stale L0/L1 representations if content changes without re-indexing
