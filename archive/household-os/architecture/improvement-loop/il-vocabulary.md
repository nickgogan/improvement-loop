# IL Vocabulary

> **For agents:** This page defines terms specific to the Improvement Loop. For cross-system terms, see Governance Vocabulary.

---

| Term | Definition |
|---|---|
| **Research Source** | A URL, video, paper, or document processed by the research-loop skill. Tracked in the Research Sources DB with processing status. |
| **Research Finding** | A distilled knowledge entry — one pattern or technique — with evidence links, applicability tags, and proposer priority. |
| **Research Authority** | A person, channel, institution, or organization identified as a valuable knowledge source. |
| **Improvement Proposal** | A proposed change to a specific system, generated by the research-proposer skill. Includes implementation complexity, operational impact, and reversibility assessment. |
| **Proposer Priority** | Priority level assigned to a Research Finding indicating how urgently it should be considered for proposal generation. |
| **Applicability** | Multi-select tag on Research Findings indicating which systems a finding is relevant to: S2, S3, Perplexity Skills, General. |
| **Delta Report** | Output of a research-loop run comparing current configurations against frontier patterns. |
| **Conflict Detection** | The Proposer's identification of mutually exclusive proposals, cross-referenced for human resolution. |
| **One-Way Door** | A proposed change that is difficult or impossible to reverse. Gets extra scrutiny. |
| **Two-Way Door** | A proposed change that can be easily reversed if it doesn't work. Lower approval threshold. |
| **Implementation Complexity** | Assessment of how hard a proposed change is to build. |
| **Ops Impact** | Assessment of how much ongoing burden a proposed change adds to system operations. |
| **Proposer Scoping Mechanism** | The process by which the Proposer determines which system documents to read, based on findings' Applicability property, capped at 8-10 documents per run (DD-31). |
| **Conflict Group** | An identifier linking mutually exclusive proposals so the human can resolve them as a set (DD-31). |
| **Partial Run** | A Proposer pipeline execution that stops after phase 3 (Grouping & Conflict Analysis) for a human gate on conflicts before generating full proposals (DD-31). |
| **Codification Pipeline** | The stage between proposal approval and system-specific deployment where approved proposals are distilled into Codified Practices (governing knowledge) before application (DD-39). |
| **Gate** | A numbered pipeline checkpoint (Gate 1, 2, 3) where Nick reviews output before the next stage proceeds. See DD-29 for gate definitions. |
| **Write Domain** | The set of databases a skill is authorized to write to. Read/write boundaries are strictly enforced per skill (DD-30). |
| **Research-Driven Improvement** | The principle that system evolution is driven by periodic external research, not ad-hoc decisions. All systems are improved through the same research pipeline (DD-36). |

*For cross-system terms (DD, IB, Human Gate, Cognitive Disposition, etc.), see Governance Vocabulary.*
